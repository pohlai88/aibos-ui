# Clean Monorepo Playbook (Node · Next · React · TypeScript)

## 0) Golden Rules (memorize these)

1. **One responsibility per package** (UI, contracts, domain, BFF, infra).
2. **No cross-layer reach-through**: UI → BFF (REST) → domain services → data/event adapters.
3. **Contracts-first**: all IO types live in `@contracts`; everything else depends on it (never the reverse).
4. **Event sourcing is internal** to domain; REST is external. Never leak event internals to UI.
5. **Everything is typed & linted**; boundaries enforced by tooling (not just conventions).

---

## 1) Repository layout (stable baseline)

```
.
├─ apps/
│  ├─ web/                # Next.js (imports UI only; no business logic)
│  ├─ bff/                # Next route handlers (REST) or Express app
│  └─ workers/            # Background workers (empty)
├─ packages/
│  ├─ accounting-contracts/ # SSOT: Zod schemas, OpenAPI, DTOs, errors
│  ├─ ui/                 # headless/presentational components & primitives
│  ├─ ui-business/        # accounting UX (hooks + containers) – calls BFF
│  ├─ accounting-web/     # Accounting-specific UI components
│  ├─ accounting/         # domain services (posting rules, MFRS logic)
│  ├─ eventsourcing/     # event store, outbox/inbox, envelopes, codecs
│  ├─ observability/     # logging, metrics, monitoring
│  ├─ policy/            # business rules, policies, validations
│  ├─ utils/             # pure utils only (no domain knowledge)
│  └─ docs/              # package-level documentation
├─ docs/                 # ADRs, architecture diagrams, contracts docs
├─ scripts/              # Build and utility scripts
├─ tests/                # Cross-package tests
├─ templates/            # Code templates
├─ turbo.json
├─ pnpm-workspace.yaml
└─ tsconfig.base.json
```

**Never** put UI logic in `apps/web`. It should **only import** from `packages/ui*`.

## 2) Contracts-first (SSOT)

* **Where**: `packages/accounting-contracts`
* **What**: Zod schemas, request/response DTOs, domain types (pure), error codes, OpenAPI generation.
* **Who depends on it**: **everyone** (BFF, UI hooks, domain services, tests).

Minimal example:

```ts
// packages/accounting-contracts/src/accounting.ts
import { z } from "zod";

export const Account = z.object({
  id: z.string().uuid(),
  accountCode: z.string().min(1),
  accountName: z.string().min(1),
  type: z.enum(["ASSET","LIABILITY","EQUITY","REVENUE","EXPENSE"]),
  normalBalance: z.enum(["DEBIT","CREDIT"]),
  parentId: z.string().uuid().nullable(),
  currency: z.string().length(3),
  isPostingAllowed: z.boolean(),
});
export type Account = z.infer<typeof Account>;

// Error model
export const ApiError = z.object({
  code: z.string(),            // e.g., "ACCOUNT_CODE_EXISTS"
  message: z.string(),         // human-readable
  details: z.unknown().optional()
});
export type ApiError = z.infer<typeof ApiError>;
```

**OpenAPI**: generate from Zod once per CI (or keep a hand-authored spec in `accounting-contracts` and validate against Zod).

## 3) REST BFF (thin & deterministic)

* **Where**: `apps/bff` (Next route handlers or Express)
* **Rules**:

  * Validate input/output with **contracts** at the boundary.
  * **No business logic** inside BFF. Call `@aibos/accounting` services.
  * Enforce **tenant isolation** and **auth** here.
  * Map domain exceptions → `ApiError`.

```ts
// apps/bff/src/app/api/accounts/route.ts
import { NextRequest, NextResponse } from "next/server";
import { Account } from "@aibos/accounting-contracts";
import * as svc from "@aibos/accounting";

export async function GET() {
  const data = await svc.listAccounts();
  return NextResponse.json(Account.array().parse(data));
}
```

## 4) Domain services (pure business logic)

* **Where**: `packages/accounting`
* **Rules**:

  * Pure business rules (posting, period locks, MFRS validations).
  * Use **ports** to talk to `@aibos/accounting/infrastructure` and `@aibos/eventsourcing`; do not import DB clients directly.
  * Emit **domain events** via `@aibos/eventsourcing` (not HTTP).

```ts
// packages/accounting/src/usecases/createAccount.ts
import { type Account } from "@aibos/accounting-contracts";
import { accountsRepo } from "@aibos/accounting/infrastructure";
import { events } from "@aibos/eventsourcing";

export async function createAccount(input: Omit<Account, "id">): Promise<Account> {
  // validations (unique code, parent existence, normalBalance by type...)
  const created = await accountsRepo.insert(input);
  await events.publish({ type: "AccountCreated", payload: { id: created.id } });
  return created;
}
```

## 5) Data access (repositories, no domain logic)

* **Where**: `packages/accounting/infrastructure` (repositories within accounting package)
* **Rules**:

  * Drizzle/Supabase queries live here.
  * Provide **interfaces/ports** for domain services; hide DB schema.
  * No business validations here; just persistence and projections.

```ts
// packages/accounting/src/infrastructure/repositories/accountsRepo.ts
import { type Account } from "@aibos/accounting-contracts";
export interface AccountsRepo {
  findAll(): Promise<Account[]>;
  insert(input: Omit<Account,"id">): Promise<Account>;
}
export const accountsRepo: AccountsRepo = /* drizzle-backed impl */;
```

## 6) Event sourcing (decoupled & versioned)

* **Where**: `packages/eventsourcing`
* **Patterns**: event **envelope**, **outbox/inbox**, **idempotency**, **schema versioning**, **rebuilders**.
* **Never** couple UI to events.

```ts
// packages/eventsourcing/src/types.ts
export type EventEnvelope<T = unknown> = {
  id: string;               // ULID
  type: string;             // e.g., "JournalPosted.v1"
  ts: string;               // ISO
  tenantId: string;
  causationId?: string;
  correlationId?: string;
  payload: T;
};
```

* **Outbox**: write domain events and commit with DB tx → background dispatcher publishes.
* **Consumers**: project to read models (e.g., trial balance snapshots) and append audit logs.

## 7) UI packages (pure; no side-effects)

* **`packages/ui`**: headless primitives (Button, Table, Modal)
* **`packages/ui-business`**: accounting pages/containers + **hooks** using fetch to BFF; **no direct domain/data import**.
* **`packages/accounting-web`**: accounting-specific UI components and widgets.

```ts
// packages/ui-business/src/hooks/useAccounts.ts
import { useQuery } from "@tanstack/react-query";
import { Account } from "@aibos/accounting-contracts";

export function useAccounts() {
  return useQuery({
    queryKey: ["accounts"],
    queryFn: async () => {
      const res = await fetch("/api/accounts");
      const json = await res.json();
      return Account.array().parse(json);
    }
  });
}
```

## 8) Boundaries enforcement (tools that make it real)

### TypeScript path aliases (`tsconfig.base.json`)

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@aibos/accounting-contracts/*": ["packages/accounting-contracts/src/*"],
      "@aibos/accounting/*": ["packages/accounting/src/*"],
      "@aibos/eventsourcing/*": ["packages/eventsourcing/src/*"],
      "@aibos/observability/*": ["packages/observability/src/*"],
      "@aibos/policy/*": ["packages/policy/src/*"],
      "@aibos/ui/*": ["packages/ui/src/*"],
      "@aibos/ui-business/*": ["packages/ui-business/src/*"],
      "@aibos/accounting-web/*": ["packages/accounting-web/src/*"],
      "@aibos/utils/*": ["packages/utils/src/*"]
    }
  }
}
```

### ESLint + boundaries (representative)

```js
// eslint/boundaries.js
export default {
  rules: {
    "boundaries/element-types": [2, { default: "disallow" }],
    "boundaries/no-private": 2,
    "boundaries/no-unknown": 2,
    "boundaries/entry-point": [2, { default: "allow" }],
    "boundaries/allowed-types": [2, {
      rules: [
        { from: ["packages/ui-business"], allow: ["packages/ui", "apps/bff", "packages/accounting-contracts"] },
        { from: ["packages/accounting-web"], allow: ["packages/ui", "packages/accounting-contracts"] },
        { from: ["apps/bff"], allow: ["packages/accounting","packages/accounting-contracts","packages/observability","packages/policy"] },
        { from: ["packages/accounting"], allow: ["packages/accounting-contracts","packages/eventsourcing","packages/observability","packages/policy","packages/utils"] },
        { from: ["packages/eventsourcing"], allow: ["packages/accounting-contracts","packages/utils"] },
        { from: ["packages/observability"], allow: ["packages/utils"] },
        { from: ["packages/policy"], allow: ["packages/accounting-contracts","packages/utils"] },
        { from: ["packages/ui"], allow: [] } // leaf library
      ]
    }]
  }
};
```

## 9) Turborepo pipeline (fast & deterministic)

```json
// turbo.json
{
  "pipeline": {
    "typecheck": { "outputs": [] },
    "lint":      { "outputs": [] },
    "build":     { "dependsOn": ["^build"], "outputs": ["dist/**", ".next/**"] },
    "test":      { "dependsOn": ["build"], "outputs": ["coverage/**"] }
  }
}
```

**Per package** ensure:

* `build` emits to `dist/`
* `typecheck` uses `tsc -b`
* `lint` runs eslint with shared config
* CI runs: `turbo run typecheck lint build test --filter=...[changed]`

---

## 10) Versioning & releases (Changesets)

* Keep **internal** packages private; publish only what’s needed.
* Use **Changesets** for semver and changelogs.
* Contracts breaking changes → **major**; REST version via `/v1`, `/v2`.

---

## 11) Testing strategy (layered)

* **contracts**: schema tests (Zod), example vectors.
* **accounting**: unit tests for posting rules, period locks, FX; property tests for balancing.
* **data**: repo integration tests (in-memory/pg test container).
* **events**: outbox/inbox idempotency & replays.
* **bff**: route tests (supertest) validating IO with contracts.
* **ui/ui-business**: component tests + hooks (MSW) + a11y (axe).

---

## 12) Security & tenancy

* **apps/bff/middleware**: auth, RBAC, `x-tenant-id`, CORS, security headers.
* **data**: Postgres RLS by tenant; set config from verified token.
* **events**: include `tenantId` in envelope, validate on consume.

---

## 13) Observability & audits

* Correlation/causation IDs propagate from web → BFF → domain → events.
* Audit as **event stream** + queryable table.
* Standard log fields: `ts, level, tenantId, actorId, route, eventType, correlationId`.

---

## 14) Developer workflow (make it easy to do the right thing)

* **Scaffold scripts** to create new use cases with correct wiring:

  * `pnpm tooling:new-usecase accounting postJournalEntry`
* **PR checklist** (short but strict):

  1. Contracts updated? Tests updated?
  2. No boundary violations (ESLint + DepCruiser green).
  3. REST IO validated at BFF.
  4. Events versioned and documented.
  5. Multi-tenant & a11y considered.

---

## 15) What NOT to do (red lines)

* UI importing `@aibos/accounting` or `@aibos/eventsourcing` directly ❌
* Domain importing `next/*` or React ❌
* BFF performing business logic ❌
* Exposing domain events to frontend ❌
* Writing to DB outside `@aibos/accounting/infrastructure` ❌

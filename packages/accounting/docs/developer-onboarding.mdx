# Developer Onboarding Guide

*A comprehensive guide for developers joining the AIBOS ERP project*

## Welcome to AIBOS ERP

Welcome to the AIBOS ERP development team! This guide will help you understand our architecture, development practices, and how to contribute effectively to our enterprise accounting system.

## Project Overview

### What is AIBOS ERP?

AIBOS ERP is a modern, enterprise-grade accounting system built with:
- **Event Sourcing**: Complete audit trail with immutable event history
- **Domain-Driven Design**: Business logic encapsulated in domain models
- **Multi-Currency Support**: Real-time FX conversion with automated rebalancing
- **Microservices Architecture**: Scalable, maintainable service-oriented design
- **TypeScript**: Type-safe development with comprehensive tooling

### Key Business Domains

1. **Accounting Core**: Chart of accounts, journal entries, general ledger
2. **Financial Reporting**: P&L, balance sheet, cash flow, financial ratios
3. **Multi-Currency**: FX conversion, rebalancing, compliance
4. **Audit & Compliance**: Complete audit trail, regulatory reporting
5. **Integration**: Third-party systems, APIs, data import/export

## Development Environment Setup

### Prerequisites

Ensure you have the following tools installed:

```bash
# Node.js (LTS version)
node --version  # Should be 18.18.0+

# pnpm (package manager)
pnpm --version  # Should be 8.0.0+

# TypeScript
npx tsc --version  # Should be 5.9.2+

# Docker (for local development)
docker --version  # Should be 20.10.0+

# Git
git --version  # Should be 2.30.0+
```

### Initial Setup

1. **Clone the repository**
```bash
git clone https://github.com/aibos-erp/aibos-erp.git
cd aibos-erp
```

2. **Install dependencies**
```bash
pnpm install
```

3. **Set up environment variables**
```bash
cp env.example .env
# Edit .env with your local configuration
```

4. **Start development services**
```bash
# Start all services with Docker Compose
docker-compose -f docker-compose.dev.yml up -d

# Or start individual services
pnpm dev:accounting
pnpm dev:bff
pnpm dev:web
```

5. **Run database migrations**
```bash
pnpm migrate:dev
```

6. **Seed development data**
```bash
pnpm seed:dev
```

## Development Workflow

### Git Workflow

We use GitFlow with feature branches:

```bash
# Create feature branch
git checkout -b feature/account-validation-improvements

# Make changes and commit
git add .
git commit -m "feat: improve account validation rules"

# Push and create PR
git push origin feature/account-validation-improvements
```

### Commit Message Convention

We follow conventional commits:

```
<type>(<scope>): <description>

[optional body]

[optional footer(s)]
```

**Types:**
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation changes
- `style`: Code style changes
- `refactor`: Code refactoring
- `test`: Test additions/changes
- `chore`: Build process or auxiliary tool changes

**Examples:**
```
feat(accounting): add multi-currency support for journal entries

fix(api): resolve validation error in account creation endpoint

docs(architecture): update event sourcing documentation
```

### Code Review Process

1. **Create Pull Request**
   - Clear title and description
   - Link to related issues
   - Add reviewers

2. **Code Review Checklist**
   - [ ] Code follows project conventions
   - [ ] Tests are included and passing
   - [ ] Documentation is updated
   - [ ] No breaking changes (or properly documented)
   - [ ] Performance implications considered

3. **Review Response**
   - Address all feedback
   - Update tests if needed
   - Squash commits if requested

## Key Concepts

### Multi-Tenancy

Every operation is scoped to a tenant:

```typescript
// Tenant context is set in middleware
@Injectable()
export class TenantInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const request = context.switchToHttp().getRequest();
    const tenantId = request.headers['x-tenant-id'];
    
    // Set tenant context for database queries
    return from(this.setTenantContext(tenantId)).pipe(
      switchMap(() => next.handle())
    );
  }
}

// All repositories use tenant context
export class TypeormAccountRepository {
  async findByCode(accountCode: string, tenantId: string): Promise<Account | null> {
    return this.repository.findOne({
      where: { accountCode, tenantId }
    });
  }
}
```

### Multi-Currency

Handle multiple currencies with FX conversion:

```typescript
// Journal entry with multiple currencies
const journalEntry = {
  entries: [
    { accountCode: 'CASH_USD', debitAmount: 1000, creditAmount: 0, currency: 'USD' },
    { accountCode: 'SALES', debitAmount: 0, creditAmount: 4200, currency: 'MYR' }
  ],
  baseCurrency: 'MYR'
};

// Automatic FX conversion
const convertedEntry = await this.multiCurrencyService.convertJournalEntry(
  journalEntry.entries,
  journalEntry.baseCurrency,
  new Date()

```

### Event Sourcing

All changes are captured as events:

```typescript
// Aggregate root with event sourcing
export class JournalEntry extends AggregateRoot {
  public postEntry(command: PostJournalEntryCommand): void {
    // Validate business rules
    this.validatePosting(command);
    
    // Update state
    this.status = JournalEntryStatus.POSTED;
    this.postedAt = new Date();
    
    // Record event
    this.addEvent(new JournalEntryPostedEvent(
      this.journalEntryId,
      this.entries,
      this.reference,
      this.description,
      this.postedBy,
      this.tenantId,
      this.getVersion() + 1
    ));
  }
}
```

## Common Patterns

### Repository Pattern

Abstract data access:

```typescript
export interface AccountRepository {
  save(account: Account): Promise<void>;
  findByCode(accountCode: string, tenantId: string): Promise<Account | null>;
  findAll(tenantId: string): Promise<Account[]>;
  delete(accountCode: string, tenantId: string): Promise<void>;
}

export class TypeormAccountRepository implements AccountRepository {
  constructor(
    @InjectRepository(AccountEntity)
    private readonly repository: Repository<AccountEntity>
  ) {}

  async save(account: Account): Promise<void> {
    const entity = this.mapToEntity(account);
    await this.repository.save(entity);
  }

  async findByCode(accountCode: string, tenantId: string): Promise<Account | null> {
    const entity = await this.repository.findOne({
      where: { accountCode, tenantId }
    });
    
    return entity ? this.mapToDomain(entity) : null;
  }
}
```

### Command Pattern

Encapsulate operations:

```typescript
export class CreateAccountCommand {
  constructor(
    public readonly tenantId: string,
    public readonly userId: string,
    public readonly accountCode: string,
    public readonly accountName: string,
    public readonly accountType: AccountType,
    public readonly parentAccountCode?: string,
    public readonly isActive: boolean = true

}

export class PostJournalEntryCommand {
  constructor(
    public readonly journalEntryId: string,

    public readonly reference?: string,
    public readonly description?: string,
    public readonly postingDate: Date = new Date(),
    public readonly tenantId: string,
    public readonly userId: string

}
```

```bash

docker ps | grep postgres

pnpm db:reset
```

### Logging

Use structured logging for debugging:

```typescript
export class AccountingService {
  private readonly logger = new Logger(AccountingService.name);

  async createAccount(command: CreateAccountCommand): Promise<void> {
```

## Best Practices

### Code Quality

1. **Type Safety**: Use TypeScript strictly, avoid `any`
2. **Immutability**: Prefer immutable data structures
3. **Pure Functions**: Write functions without side effects
4. **Error Handling**: Use proper error types and handling
5. **Documentation**: Document public APIs and complex logic

### Performance

1. **Database Queries**: Use proper indexes and query optimization
2. **Caching**: Cache frequently accessed data
3. **Pagination**: Implement pagination for large datasets
4. **Async Operations**: Use async/await properly
5. **Memory Management**: Avoid memory leaks in long-running processes

### Security

1. **Input Validation**: Validate all inputs
2. **SQL Injection**: Use parameterized queries
3. **Authentication**: Implement proper authentication
4. **Authorization**: Check permissions for all operations
5. **Audit Trail**: Log all sensitive operations

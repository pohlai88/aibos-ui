## Architecture Patterns

### Domain-Driven Design

The package follows DDD principles with clear separation:

- **Domain Layer**: Pure business logic (`src/domain/`)
- **Application Layer**: Use cases and orchestration (`src/services/`)
- **Infrastructure Layer**: External concerns (`src/infrastructure/`)
- **Interface Layer**: API and contracts (`src/api/`)

### Event Sourcing

Complete event sourcing implementation:

- **Events**: Domain events (`src/events/`)
- **Event Store**: Immutable event storage (`src/infrastructure/`)
- **Projections**: Read model updates (`src/projections/`)
- **Commands**: Business operations (`src/commands/`)

### Clean Architecture

Layered architecture with dependency inversion:

```
┌─────────────────────────────────────┐
│           API Layer                 │
├─────────────────────────────────────┤
│        Application Layer           │
├─────────────────────────────────────┤
│          Domain Layer               │
├─────────────────────────────────────┤
│       Infrastructure Layer         │
└─────────────────────────────────────┘
```

## Development Workflow

### File Organization Principles

1. **Single Responsibility**: Each file has one clear purpose
2. **Cohesion**: Related functionality grouped together
3. **Coupling**: Minimal dependencies between layers
4. **Naming**: Clear, descriptive file and directory names
5. **Consistency**: Uniform structure across all modules

### Import/Export Strategy

```typescript
// Main package exports (src/index.ts)
export * from './domain';
export * from './services';
export * from './api';
export * from './events';

// Module-specific exports
export { AccountingService } from './services/accounting.service';
export { Account } from './domain/account.domain';
export { JournalEntry } from './domain/journal-entry';
```

### Testing Strategy

- **Unit Tests**: Test individual components in isolation
- **Integration Tests**: Test component interactions
- **Service Tests**: Test business logic orchestration
- **Test Doubles**: Mock external dependencies

## Best Practices

### Code Organization

1. **Domain First**: Start with domain models and business rules
2. **Event Sourcing**: Capture all changes as events
3. **Type Safety**: Use TypeScript strictly throughout
4. **Validation**: Validate inputs at boundaries
5. **Error Handling**: Comprehensive error handling and logging

### File Naming Conventions

- **Domain Models**: `*.domain.ts`
- **Services**: `*.service.ts`
- **Entities**: `*.entity.ts`
- **Events**: `*.event.ts`
- **Commands**: `*.command.ts`
- **Tests**: `*.test.ts` or `*.spec.ts`

### Documentation Standards

- **README Files**: Module-level documentation

# AIBOS Utils Package Approval Workflow

## Overview

This document outlines the approval process for making changes to the `@aibos/utils` package, which is locked to prevent unauthorized modifications.

## Lock Status

- **Status**: ACTIVE
- **Lock Date**: 2024-12-19
- **Reason**: Production stability and API consistency

## Protected Files

The following files require approval before modification:

- `src/index.ts` - Main exports
- `src/security.ts` - Security utilities
- `src/safe-object.ts` - Safe object operations
- `src/safeFs.ts` - Safe filesystem operations
- `src/type-guards.ts` - Type guard utilities
- `src/code-quality.ts` - Code quality utilities
- `package.json` - Package configuration
- `tsconfig.json` - TypeScript configuration
- `tsup.config.ts` - Build configuration

## Approval Process

### Step 1: Create Change Request

1. Create a detailed change request document
2. Include:
   - Description of proposed changes
   - Justification for the changes
   - Impact analysis
   - Testing plan
   - Rollback plan

### Step 2: Get Approval

1. Submit change request to package maintainer
2. Wait for formal approval
3. Receive approval signature/token

### Step 3: Update Lock File

1. Add approval signature to `.lockfile`
2. Update lock status if needed
3. Document the approved changes

### Step 4: Make Changes

1. Implement approved changes
2. Run tests to ensure functionality
3. Update documentation if needed

### Step 5: Complete Process

1. Update `.lockfile` with completion signature
2. Run integrity check
3. Commit changes with approval reference

## Emergency Procedures

### Critical Security Fixes

For critical security issues:

1. Document the security issue
2. Get expedited approval from security team
3. Implement fix immediately
4. Update lock file retroactively
5. Notify all stakeholders

### Rollback Procedure

If changes cause issues:

1. Revert to last known good state
2. Update lock file with rollback signature
3. Document the issue and resolution
4. Review approval process

## Compliance Requirements

### Documentation

- All changes must be documented
- Approval signatures must be recorded
- Change impact must be assessed

### Testing

- All changes must pass existing tests
- New functionality must have tests
- Performance impact must be measured

### Security

- Security implications must be reviewed
- No breaking changes without major version bump
- Backward compatibility must be maintained
